# M0 검증 기록

측정일 2026-11-17 · 측정 앱: `app/src/main/java/app/conversate/glass/probe/ProbeActivity.kt`

## 빌드 환경

- Android SDK: `$env:LOCALAPPDATA\Android\Sdk` (platform 35, build-tools 35.0.0과 34.0.0)
- Gradle 8.11.1 래퍼, Android Gradle Plugin 8.7.3, Kotlin 2.0.21, JDK 21
- 빌드와 설치:

```bash
./gradlew.bat assembleDebug
```

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 확인된 것

### 마이크

안경 스피커로 한국어 음성 샘플을 틀면서 소스별로 2초씩 녹음했다. 값은 평균/가장 큰 100ms 구간의 dBFS다.

| 소스 | 조용할 때 | 음성 재생 중 | 판정 |
|---|---|---|---|
| UNPROCESSED 16k 모노 | -74 / -70 | -50 / -43 | **사용.** 24dB 이상 상승 |
| UNPROCESSED 48k 스테레오 | -75 / -73 | 좌 -51 / -45, 우 -58 / -52 | 마이크 두 개가 따로 들어옴 |
| MIC 48k 스테레오 | -84 / -82 | -55 / -43 | 사용 가능 |
| MIC 16k 모노 | -79 / -73 | -68 / -61 | 반응이 약함 |
| CAMCORDER 16k | -79 / -74 | -71 / -64 | 반응이 약함 |
| VOICE_COMMUNICATION 16k | -83 / -81 | -73 / -65 | 반응이 약함 |
| VOICE_RECOGNITION 16k | -90 / -90 | -90 / -90 | **사용 불가.** 항상 0 |

- 앱이 화면 맨 위에 있을 때 녹음 트랙은 무음 처리되지 않았다.
- 전체 레벨이 낮다. STT로 보내기 전에 20~30dB 디지털 증폭이 필요하다.
- 스피커가 마이크 바로 옆이라 이 결과는 가까운 소리 기준이다. 떨어진 거리는 아래 남은 측정에서 본다.

### 화면

- 프레임은 480×640 세로다. 한글 폰트가 정상 렌더링된다.
- 한 줄에 들어가는 한글 수: 12sp 28자, 14sp 25자, 16sp 21자, 18sp 19자, 20sp 17자, 24sp 14자.
- 시스템 화면 꺼짐 시간이 10초다. 앱은 화면 켜짐 유지 플래그를 써야 한다.
- 착용자가 눈금 화면에서 읽은 범위: 세로 y40부터 y560, 가로 x80부터 x400 눈금. 가로 눈금은 x80~x400만 그렸으므로 가로는 전부 보인 것이다. 세로는 y600 눈금이 안 보였다. 안전 영역은 y40~y560으로 잡는다.

### 런처와 입력

- 런처 기능 목록(번역, 프롬프터, 음악, 카메라, Vision AI, 자막, 기기 정보) 끝에 Conversate가 나타나고 탭으로 실행된다.
- 터치패드가 보낼 수 있는 키: ENTER, UP, DOWN, LEFT, RIGHT, BACK, PROG1~3, F13, F14, DASHBOARD.

착용자가 직접 한 제스처를 커널 입력과 앱 로그 양쪽에서 기록한 결과다.

| 제스처 | 커널 키 | 앱이 받는 키 | 비고 |
|---|---|---|---|
| 손가락 닿음 | DASHBOARD | NOTIFICATION | 모든 터치의 시작에 온다 |
| 탭 | ENTER | ENTER | 닿은 뒤 0.5~0.6초 뒤에 온다. 두 번 탭 판정을 기다리는 시간 |
| 두 번 탭 | BACK | BACK | 두 번째 터치 0.3초 뒤 |
| 길게 누르기 | PROG1을 누른 채 유지 | 오지 않음 | 시스템이 `ACTION_AI_START`로 AI 비서를 띄운다. 비서가 닫힐 때까지 앱은 입력을 못 받는다 |
| 앞으로 쓸기 | RIGHT 1~2회 뒤 DOWN 1회 | DPAD_RIGHT, DPAD_DOWN | 12회 측정. DOWN은 매번 정확히 한 번, 마지막에 온다 |
| 뒤로 쓸기 | LEFT 1~2회 뒤 UP 1회 | DPAD_LEFT, DPAD_UP | 12회 측정. UP은 매번 정확히 한 번, 마지막에 온다 |

- 쓸기 한 번은 닿은 뒤 0.1~0.4초 안에 끝난다. 탭과 달리 기다리는 시간이 없다.
- 앱은 DPAD_DOWN을 다음, DPAD_UP을 이전으로 쓰면 쓸기 한 번이 정확히 한 칸이 된다.

- 키 배치 파일에 `SPRITE_SWIPE_FORWARD`, `SPRITE_SWIPE_BACK`, `SPRITE_DOUBLE_TAP`라는 전용 키가 정의돼 있지만, 측정에서는 방향키와 BACK이 왔다.
- AI 비서 로그에서 `vendor.rkd.glasses.is_take_on`(착용)과 `vendor.rkd.glasses.is_spread`(다리 펼침) 속성을 읽는 것이 보였다. 미착용 자동 일시정지에 쓸 수 있다.
- 시스템이 우리 앱을 `third_app` 장면으로 인식하고, AI 비서를 열 때도 닫지 않는다.

### 네트워크

- 안경(10.0.1.230)에서 PC(10.0.11.11)로 TCP 연결이 된다. 배터리 측정 때 PC가 수신기 역할을 할 수 있다.

### 기본 자막 기능 조사

> 2026-11-17 후속 검증: **기본 자막 화면 없이 폰에 시작 명령을 직접 보내는 방식이 실제로 동작했다.** 일반 앱에서 중간/확정 결과 수신, 앱 생존, 종료 시 오디오 스트림 해제를 확인했다. 구현과 증거는 [ROKID-STT.md](ROKID-STT.md) 참조. 아래는 후속 검증 전의 초기 조사 기록이다.

Rokid AI가 쓰는 음성 인식을 빌려 쓸 수 있는지 보려고 런처의 "자막" 기능을 켜고 시스템 로그를 읽었다.

- 안경에는 표준 Android 음성 인식 서비스가 없다.
- Rokid AI 서비스(`AIUIService`)는 서명 권한으로 잠겨 있어 다른 앱이 붙을 수 없다.
- "자막"은 내부적으로 `accessibility` 장면이다. 켜면 안경이 블루투스로 폰의 Rokid 앱에 `Accessibility_start`를 보내고, 인식 결과가 폰에서 안경으로 돌아온다. 음성 인식은 안경이 아니라 폰과 Rokid 서버에서 돈다.
- 결과는 `{"content":"...","final":false,"number":1,"role":""}` 형태로 오고, 말하는 도중의 중간 결과와 확정 결과가 구분된다. 한국어가 인식됐다. 화자를 뜻하는 것으로 보이는 `role` 칸도 있다.
- 이 결과를 `MasterAssistService`가 연결된 내부 클라이언트 전체에 뿌린다(`notifyAll=true`). 이 서비스는 권한 없이 공개돼 있다. 우리 앱이 여기에 붙어 자막 텍스트를 받을 수 있을 가능성이 있다. 인터페이스는 비공개라 Rokid 시스템 앱을 분석해야 알 수 있다.
- 걸림돌: 자막 장면이 열릴 때 시스템이 실행 중인 서드파티 앱을 강제 종료한다(`forceStopPackage app.conversate.glass` 확인). AI 비서 장면은 서드파티 앱을 닫지 않는다.
- 설계 반영: 시스템이 우리 앱을 예고 없이 강제 종료할 수 있으므로 세션 기록은 발화가 확정될 때마다 바로 저장한다.

### 배터리 측정 절차

PC에서 수신기를 띄운다.

```bash
python tools/battery_sink.py --minutes 60
```

안경에서 배터리 쪽을 업로드 부하와 함께 연다.

```bash
adb shell am start -n app.conversate.glass/.probe.ProbeActivity --ei page 3 --es sink 10.0.11.11:8765
```

USB를 뽑으면 측정이 시작된다. 화면, 마이크, 초당 32KB 업로드가 모두 켜진 상태로 60분 뒤 결과가 `tools/out/battery_sink.csv`에 남는다.
