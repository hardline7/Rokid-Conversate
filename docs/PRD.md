# Rokid Conversate PRD v0.4

> 수정일 2026-11-17 · v0.2에서 생성 AI도 Rokid 기반으로 변경했습니다.
> 표기: ✅ 실기기 또는 공식 자료로 확인함 · ⚠️ 아직 확인 못 함

> 현재 구현은 기본 STT와 정식 AIUI LanguageModel 도우미를 사용하는 **Rokid 전용 경로**다. **폰의 Rokid 앱 연결이 필요하며 별도 LLM API 키는 사용하지 않는다.** [사용법](USAGE.md), [구현·검증 범위](BUILD-STATUS.md), [STT 근거](ROKID-STT.md).

## 0. 한 줄 요약

Even Realities G2의 **Conversate**와 같은 경험을, 지금 가진 **Rokid Glasses 한 대에서 단독으로 도는 앱**으로 만든다. 판매용 제품이 아니라 본인이 실제 회의에서 쓰는 도구가 목표다.

## 1. 목표와 범위

**목표:** Conversate의 대화 전, 중, 후 흐름을 빠짐없이 재현한다.

| 단계 | 재현할 것 |
|---|---|
| 대화 전 | Prep Notes로 사전 자료를 넣어 둔다 |
| 대화 중 | 발화 묶음 요약을 렌즈 상단에 유지, 스와이프로 요약 탐색, 전문 용어 풀이, 선택형 실시간 자막, AI Cue, 탭으로 화면 전환 |
| 대화 후 | 자동 제목이 붙은 기록. 발화 묶음, Summary, Cue List, Transcription 탭. 검색 |
| 원칙 | 음성은 저장하지 않는다. 켰을 때만 동작한다. 자막, 요약, Cue를 각각 끌 수 있다 |

**범위 밖:** 구독과 과금, 다중 사용자 계정, iOS/Android 폰 앱, 엔터프라이즈 관리 기능, 얼굴 인식, 화상회의 오디오 연동, Rokid 스토어 배포.

## 2. 기준선: Conversate는 실제로 이렇게 동작한다

재현 대상의 정의다. 공개 자료에서 확인된 것만 적었다.

| 항목 | Conversate 동작 | 출처 |
|---|---|---|
| Prep Notes 작성 | 폰 앱에서 메모를 쓰거나 파일을 올린다. 문서에서 맥락만 추출하고 원본 파일은 저장하지 않는다 | 공식 페이지 |
| Prep Notes 개수 | 계정당 최대 100개 | 지원 문서(검색 요약) |
| 시작 | 음성 명령 또는 폰 앱에서 시작 | 지원 문서(검색 요약) |
| Live Transcript | 대화가 실시간 자막으로 렌즈에 표시된다 | 공식 페이지, 리뷰 |
| AI Cue: Suggestions | 요점을 확인하거나, 주장에 반박하거나, 대화 방향을 바꾸는 제안 | 공식 페이지 |
| AI Cue: Answers | 올려 둔 자료에서 찾은 근거. 필요한 순간에 사실을 띄운다 | 공식 페이지 |
| AI Cue: Concepts | 전문 용어와 낯선 개념 설명 | 공식 페이지 |
| AI Cue: Bios | 대화에 언급된 인물의 간단한 배경 | 공식 페이지 |
| Cue 표시 방식 | 관련 있을 때 자동으로 나타나고 몇 초 뒤 사라진다 | 공식 페이지 |
| 화면 전환 | 안경 탭 또는 R1 링 탭으로 자막, 실시간 제안, Prep Notes 사이를 전환 | 보도자료(2026-03-26) |
| AI Summary | 대화 중 백그라운드에서 핵심과 액션아이템을 모은다 | 공식 페이지 |
| 대화 후 기록 | 자동 생성 제목. Summary, Cue List, Transcription으로 나뉜다 | 지원 문서(검색 요약) |
| Summary 구성 | 개요, 핵심 결론, 논의 사항, 다음 단계 | 지원 문서(검색 요약) |
| 검색 | 제목이나 내용으로 지난 세션 검색. 오프라인에서도 가능 | 지원 문서(검색 요약) |
| 프라이버시 | 음성 미저장. 텍스트와 요약만 저장. 기능별 끄기 가능 | 공식 페이지 |
| 요구 조건 | 폰을 통한 인터넷 연결 필수 | 공식 페이지 |

⚠️ **모르는 것:** G2 렌즈의 정확한 화면 배치, Cue가 유지되는 정확한 초 수, 지원 언어 목록, 화자 구분 여부. 지원 문서 원문은 접근이 막혀 검색 요약으로만 확인했다. 이 부분은 5장에서 직접 설계했고, 실물이나 영상을 보면 맞춰 고친다.

## 3. 우리 기기에서 확인한 사실

PC에 연결된 안경을 adb로 직접 조사한 결과다.

| 항목 | 결과 |
|---|---|
| 기기 | ✅ Rokid RG-glasses, Android 12(API 32) |
| 화면 | ✅ 480×640 세로, 밀도 240dpi, 단색 그린 |
| 앱 설치 | ✅ adb 접속 가능. 서드파티 앱은 현재 0개 |
| 네트워크 | ✅ Wi-Fi로 인터넷 직접 연결됨 |
| 터치패드 | ✅ 표준 키 이벤트 전달(ENTER, 상하좌우, BACK 외 기능 키 몇 개) |
| 마이크 | ✅ 내장 마이크 장치 존재 |
| 앱에서 마이크 녹음 | ✅ 가능. 단 소스를 가린다. `UNPROCESSED`는 음성에 반응하고, `VOICE_RECOGNITION`은 항상 0만 나온다 |
| 마이크 채널 | ✅ 48kHz 스테레오에서 좌우 레벨이 7dB 다르다. 서로 다른 마이크 두 개가 따로 들어온다 |
| 글자 수 | ✅ 한 줄 한글 수: 14sp 25자, 16sp 21자, 18sp 19자, 20sp 17자 |
| 런처에 앱 표시 | ✅ 런처 기능 목록 마지막에 Conversate가 뜨고 탭으로 실행된다 |
| 제스처와 키 대응 | ✅ 탭은 ENTER, 두 번 탭은 BACK, 앞으로 쓸기는 RIGHT와 DOWN, 뒤로 쓸기는 LEFT와 UP. 길게 누르기는 시스템 AI 비서가 가져간다 |
| 착용 감지 | ✅ 시스템 속성 `vendor.rkd.glasses.is_take_on`으로 착용 여부를 읽을 수 있다 |
| 상대방 목소리 수음 | ⚠️ 미확인. 1~2m 거리 실측 필요 |
| 눈에 보이는 영역 | ✅ 착용자 확인. 세로는 y40부터 y560까지, 가로는 x80부터 x400 눈금까지 보인다. 아래쪽 약 80px은 안 보인다 |
| 연속 사용 배터리 | ⚠️ 미확인. 측정 도구 준비됨(`tools/battery_sink.py`) |

측정 상세는 `docs/M0.md`에 있다.

**설계 결론:** 안경에 설치하는 Android 앱이 UI·자료·기록을 소유한다. STT는 폰의 Rokid 앱과 연결된 기본 경로, 생성 AI는 공식 AIX 도우미 위젯의 LanguageModel을 사용한다. 개인 개발 설치이며 스토어 배포는 범위 밖이다.

## 5. 렌즈 화면

화면은 480×640, 배경은 검정(렌즈에서는 투명), 글자는 그린이다. 위계는 밝기와 굵기로만 표현한다. 시야 가운데는 비운다.

**안전 영역:** 모든 내용은 y40~y560, x16~x464 안에 그린다. 프레임 아래쪽 80px은 눈에 보이지 않으므로 비워 둔다. 쓸 수 있는 높이는 520px이다.

**뷰 세 개를 탭으로 순환한다.**

```
① 자막 뷰 (기본)         ② Cue 뷰                ③ Prep Notes 뷰
┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐
│ ● LIVE 12:04   62% │  │ ● LIVE 12:04   62% │  │ PREP 2/5       62% │
│ [답변] 리텐션       │  │                    │  │                    │
│ M12 41% · 업계 25% │  │ [답변] 리텐션       │  │ 핵심 수치           │
│ (IR덱 p.7)         │  │ M12 리텐션 41%     │  │ · ARR 12억         │
│                    │  │ 업계 평균 25%      │  │ · M12 리텐션 41%   │
│     (비움)          │  │ (IR덱 p.7)         │  │ · 런웨이 14개월    │
│                    │  │                    │  │                    │
│ 작년 대비 리텐션이   │  │     (비움)          │  │                    │
│ 어떻게 개선됐는지    │  │                    │  │                    │
│ 말씀해 주실 수_     │  │ 직전 Cue 1/7       │  │ ◀ 이전   다음 ▶   │
└────────────────────┘  └────────────────────┘  └────────────────────┘
```

- **자막 뷰:** 하단에 자막 3줄이 흐른다. Cue가 생기면 상단에 떴다가 사라진다.
- **Cue 뷰:** 자막 없이 Cue만 크게 보인다. 스와이프로 지난 Cue를 다시 본다.
- **Prep Notes 뷰:** 사전 자료에서 뽑은 토킹포인트를 한 장씩 넘겨 본다.

**조작**

| 동작 | 앱이 받는 키 | 기능 |
|---|---|---|
| 탭 | ENTER (0.5~0.6초 뒤 도착) | 대기 화면에서는 세션 시작. 세션 중에는 다음 뷰로 전환 |
| 앞으로 쓸기 | RIGHT 1~2회 뒤 DOWN 1회 | Cue 뷰와 Prep Notes 뷰에서 다음 |
| 뒤로 쓸기 | LEFT 1~2회 뒤 UP 1회 | Cue 뷰와 Prep Notes 뷰에서 이전 |
| 두 번 탭 | BACK | 떠 있는 Cue 닫기. Cue가 없으면 종료 확인 화면 |
| 길게 누르기 | 앱에 오지 않음 | 시스템이 AI 비서를 띄운다. 쓰지 않는다 |

- 손가락이 닿는 순간마다 NOTIFICATION 키가 먼저 온다. 앱은 무시한다.
- 쓸기 한 번에 키가 2~3개 오지만 DOWN이나 UP은 정확히 한 번씩 온다. 앱은 DOWN을 다음, UP을 이전으로 쓰고 RIGHT와 LEFT는 무시한다.
- 길게 누르기를 못 쓰므로 세션 시작은 대기 화면의 탭으로, 종료는 두 번 탭 뒤 확인으로 한다.

**Cue 규칙**

- 한 번에 하나만 보인다. 8초 유지 후 1초 동안 사라진다.
- 제목 16자 이내, 본문 36자 이내, 명사형으로 끝낸다. 숫자는 아라비아 숫자로 쓴다.
- 우선순위는 Answers, Bios, Concepts, Suggestions 순이다.
- Cue 사이 간격은 최소 4초, 분당 최대 4개다.
- 같은 용어의 Concepts는 세션당 한 번만 띄운다.

## 6. 시스템 구조

```
[Rokid Glasses 앱]
  Rokid 기본 자막/연결된 폰 ─► 비공개 STT 클라이언트 ─► 전사 저장
                                                              │
     렌즈 화면 ◄── 화면 관리자 ◄── Cue 큐 ◄── Cue 엔진 ◄───────┤
                                              │               │
                              Rokid AIUI LanguageModel ◄── 요약 엔진, 리캡
                                     ▲ 내부 인증 루프백 연결
                               프로젝트 AIX 도우미 위젯
  내장 HTTPS 서버 ◄──── 폰/PC 브라우저 (Prep Notes, 설정, 기록, 시작/종료)
  저장소: 세션 기록, Prep Notes (암호화 파일)
```

| 구성 요소 | 선택 | 이유 |
|---|---|---|
| 앱 | Kotlin Android 앱·포그라운드 서비스 | 렌즈 UI와 자료·기록 관리 |
| STT | ✅ Rokid 기본 자막 | 별도 STT 계정 없이 연결된 폰 사용. 비공개 규약 |
| 실시간 Cue·증분 요약·리캡 | ✅ 공식 AIX LanguageModel | 호스트의 Rokid AI 계정 경로. 외부 API 키 없음 |
| Prep Notes 활용 | 회의별 자료 스냅샷, Cue 요청에 원문 제공 | Answers·Bios 근거 검증. 요약에는 자료를 대화 사실로 제공하지 않음 |
| 컴패니언 | 안경 내장 HTTPS 서버, PIN·세션 쿠키 | 별도 폰 앱 없이 로컬 브라우저 사용 |

**Cue 생성 방식:** 확정된 발화의 최근 대화와 자료를 Rokid AI에 보낸다. 모델이 Cue가 필요한지와 유형을 JSON으로 답하고, 앱은 길이·확신도·원문 인용·숫자·표시 빈도를 검증한다. 질문 감지 규칙으로 가짜 생성 결과를 대신하지 않는다.

**잘못된 정보 방지**

- Answers와 Bios는 Prep Notes에 근거가 있을 때만 띄우고 출처를 붙인다.
- Answers 본문의 숫자가 Prep Notes 원문에 실제로 있는지 앱에서 한 번 더 대조한다.
- Bios는 Prep Notes에 적힌 인물만 다룬다. 웹 검색은 하지 않는다.
- 모델의 확신도가 0.8 아래이거나 검증에 실패하면 띄우지 않는다.

**알려진 한계:** 화자 구분이 없다. 본인이 한 질문에도 Answers가 뜰 수 있다. 실사용에서 거슬리면 그때 다룬다.

## 7. 데이터와 프라이버시

- 오디오는 메모리에서만 처리하고 파일로 쓰지 않는다.
- 저장하는 것은 전사 텍스트, Cue, 요약, Prep Notes 텍스트뿐이다. 안경 내부에 암호화해 둔다.
- 세션은 직접 시작했을 때만 동작하고, 화면에 `● LIVE`를 항상 표시한다.
- 시작할 때 "참석자에게 알렸습니다" 확인을 한 번 거친다.
- 기본 STT 및 생성 요청은 Rokid 서비스로 전달된다. 계정·서버의 보관 정책은 앱이 제어하지 못하며 미보관을 보장하지 않는다.
- 별도 API 키 입력은 없다. Rokid 계정 자격증명도 회의 APK로 복사하지 않는다.

화면을 벗어나면 일시정지하고, 인식된 발화가 10분 없으면 자동 종료한다. 강제 종료 후에는 중단 기록을 복구하며 자동으로 녹음을 재개하지 않는다.

## 8. 만드는 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0 검증** | 빌드 환경 설치. 측정용 앱으로 마이크 녹음, 1~2m 거리 수음, 한글 가독성, 키 대응, 60분 배터리, 런처 표시 확인 | 3장의 ⚠️ 항목이 전부 ✅ 또는 대안 확정 |
| **M1 자막** | 마이크, STT, 자막 뷰 | 말한 뒤 1.5초 안에 렌즈에 자막 |
| **M2 Prep Notes** | 내장 웹 서버, PIN, Prep Notes 작성과 업로드, Prep Notes 뷰 | 폰 브라우저로 올린 자료가 렌즈에서 넘겨짐 |
| **M3 Cue** | Concepts, Answers, Bios, Suggestions. 큐, 페이드, Cue 뷰 | 질문이 끝나고 3초 안에 Cue 표시 |
| **M4 기록** | 증분 요약, 종료 시 리캡, 기록 3개 탭, 검색, Markdown 내보내기 | 종료 30초 안에 Summary 완성 |
| **M5 다듬기** | 기능별 토글, 글자 크기, 오프라인 표시, 무음 자동 종료, 60분 안정성 | 실제 회의 3건 완주 |

**M0에서 막힐 때의 대안**

| 막히는 지점 | 대안 |
|---|---|
| 앱이 마이크를 못 쓴다 | 폰 중계 구조(v0.1의 CXR-L 경로)로 전환 |
| 상대 목소리가 약하다 | 폰을 테이블에 두고 폰 마이크를 웹 페이지로 전송 |
| 60분을 못 버틴다 | 화면 밝기와 갱신 줄이기, 보조 배터리 액세서리 |
| 런처에 앱이 안 보인다 | 웹 페이지나 PC에서 실행. 이후 Rokid SDK로 원격 실행 검토 |

## 9. 시작 전에 정할 것

1. **개발 환경:** 현재 SDK·Gradle·JDK와 앱 빌드가 준비돼 있다.
2. **Rokid 앱:** 폰에 로그인하고 안경과 연결한다.
3. **AI 도우미:** 공식 AIX 개발 경로로 이 프로젝트의 위젯을 설치한다. 현재 기기에는 설치했다.
4. **관리 화면:** 안경과 통신할 수 있는 네트워크의 브라우저에서 주소·PIN으로 접속한다.
